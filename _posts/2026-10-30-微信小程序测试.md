# 微信小程序测试 完整系统学习大纲

> 本文面向**测试工程师**，按"认知 → 环境 → 专项测试点 → 性能 → 自动化 → 兼容 → 常见问题"的顺序组织，由浅入深。
> 小程序不是"手机上的网页"，也不是原生 App——它有自己的**双线程架构、生命周期、路由栈、授权体系和审核规范**。功能测试能覆盖一半，另一半必须靠这些专属知识。

## 一、小程序概述与测试特点

### 1.1 什么是微信小程序？

*   **定义**：运行在**微信客户端内部**的轻量级应用，2017 年发布，无需下载安装，用完即走。
*   **技术栈**：`WXML`（结构）+ `WXSS`（样式）+ `JS`（逻辑）+ `JSON`（配置），开发体验接近前端，但**没有 DOM 和 BOM**。
*   **运行环境**：微信客户端提供的基础库（微信版本决定基础库版本范围）。

### 1.2 小程序 vs App vs H5

| 维度 | 小程序 | 原生 App | H5（手机网页） |
| :--- | :--- | :--- | :--- |
| 安装 | 无需安装 | 需下载安装 | 无需 |
| 入口 | 微信内（扫码/分享/搜索/下拉） | 桌面图标 | 浏览器/微信内打开 |
| 审核 | **需微信审核** | 应用商店审核 | 无 |
| 能力 | 微信开放能力（支付/登录/订阅消息） | 系统全部能力 | 受限 |
| 性能 | 接近原生（双线程 + 原生组件） | 最优 | 一般 |
| 更新 | 服务端发版，用户无感 | 需重新下载 | 实时 |
| 体积 | 主包 ≤ 2MB | 无硬限制 | 无 |
| 跨平台 | 一套代码 iOS+Android | 两套 | 一套 |

> 💡 **测试含义**：小程序**没有安装卸载**，所以"安装测试"变成"首次打开/版本更新测试"；没有应用商店，所以**审核规范**成了必须测的一项。

### 1.3 技术架构（双线程模型）

```text
┌──────────────────────────────────────────────┐
│  视图层（WebView / Skyline）                  │
│  · 渲染 WXML + WXSS                          │
│  · 可以有多个（每个页面一个）                 │
└───────────────┬──────────────────────────────┘
                │  ① setData 传数据
                │  ② 事件绑定回传
┌───────────────┴──────────────────────────────┐
│  Native 层（微信客户端 / WeixinJSBridge）     │
│  · 中转通信、转发原生能力（支付/定位/相机）   │
└───────────────┬──────────────────────────────┘
                │
┌───────────────┴──────────────────────────────┐
│  逻辑层（AppService，JSCore）                 │
│  · 执行 JS、处理数据、调 wx.xxx API           │
│  · 无 DOM、无 BOM、无 window/document         │
└──────────────────────────────────────────────┘
```

**对测试的影响：**

| 架构特点 | 引发的问题 |
| :--- | :--- |
| 逻辑层与视图层分离通信 | **`setData` 是性能瓶颈**，数据量大/调用频繁会卡顿 |
| 无 DOM | 传统 Web 自动化（Selenium）**不能直接操作** |
| 依赖微信基础库 | **基础库版本兼容**是线上问题高发区 |
| 页面栈最多 10 层 | 连续跳转超过 10 层后 `navigateTo` 失败 |
| 原生组件层级最高 | `video/map/canvas` 会**盖住**普通元素（z-index 失效） |

### 1.4 小程序的三种版本

| 版本 | 来源 | 谁能访问 | 测试用途 |
| :--- | :--- | :--- | :--- |
| **开发版** | 开发者工具"预览"生成的二维码 | 开发者本人 + 项目成员 | 开发自测 |
| **体验版** | 开发者工具"上传"，后台设为体验版 | 体验成员（需在后台配置） | ★ **测试主用** |
| **正式版** | 提交审核通过并发布 | 全部微信用户 | 线上验证 |

> ⚠️ **测试同学第一件事**：把自己加进小程序后台的"成员管理 → 体验成员"，否则扫不了体验版二维码。

## 三、小程序专项测试点（重点）

### 3.1 生命周期与页面栈

**应用生命周期：**

| 回调 | 触发时机 | 测试点 |
| :--- | :--- | :--- |
| `onLaunch` | 小程序初始化（全局一次） | 全局数据、登录态初始化 |
| `onShow` | 启动或从后台切前台 | **切后台再回来**数据是否刷新 |
| `onHide` | 切后台 | 是否暂停定时器/音视频 |
| `onError` | JS 错误 | 是否有上报 |
| `onPageNotFound` | 页面不存在 | 是否有兜底页 |

**页面生命周期：**

```text
onLoad( options )   页面加载，可拿到 URL 参数 ★
onShow              页面显示（每次切前台/返回都触发）
onReady             首次渲染完成
onHide              页面隐藏（navigateTo 到新页、切后台）
onUnload            页面卸载（redirectTo / navigateBack）
```

> 💡 **高频 Bug**：把"每次进入都要刷新"的逻辑写在 `onLoad` 里，但从子页面返回时只触发 `onShow` 不触发 `onLoad` → **数据不刷新**。
> **测试方法**：A 页 → 进入 B 页修改数据 → 返回 A 页 → 看 A 页数据是否已更新。

**页面栈（最多 10 层）：**

| API | 行为 | 页面栈 |
| :--- | :--- | :--- |
| `wx.navigateTo` | 保留当前页，跳转 | +1（**上限 10 层**） |
| `wx.redirectTo` | 关闭当前页，替换 | 不变 |
| `wx.switchTab` | 跳 tabBar 页（**不能带参数**） | 清空非 tab 页 |
| `wx.reLaunch` | 关闭所有页面，打开新页 | 清空 |
| `wx.navigateBack` | 返回（delta 指定层数） | -delta |

**测试点：**
- [ ] 连续跳转 10 层后，第 11 次 `navigateTo` 是否失败并有兜底
- [ ] `switchTab` 传参数会丢失（验证开发是否用了别的方案传值）
- [ ] `navigateBack` 返回后数据是否刷新
- [ ] 支付完成后用 `redirectTo`/`reLaunch` 而非 `navigateTo`（避免返回到支付页重复支付）

### 3.2 入口与场景值（小程序特有）

**场景值 `scene`** 标识用户从哪个入口进来，通过 `onLoad(options)` / `wx.getLaunchOptionsSync()` 获取：

| scene | 入口 | 测试必测 |
| :--- | :--- | :--- |
| 1001 | 发现页"小程序"主入口 | ★ |
| 1011 | 扫描二维码 | ★ |
| 1007 / 1008 | 好友/群聊会话中的小程序卡片 | ★ |
| 1035 | 公众号自定义菜单 | ★ |
| 1036 | App 分享消息卡片 | |
| 1058 | 公众号文章 | |
| 1089 | 微信聊天主界面下拉 | |
| 1014 | 小程序码（圆形） | ★ |

**测试矩阵：**

```text
□ 扫码进入（二维码 + 小程序码，带 scene 参数）
□ 分享卡片进入（好友 / 群聊）
□ 公众号菜单 / 文章进入
□ 微信搜索进入
□ 下拉"最近使用"进入
□ 朋友圈（"分享到朋友圈"是单页模式，能力受限 ★）
□ 直接打开（已使用过的小程序）
□ 外部 App 跳转

每个入口都要验证：
  · 页面是否正确（是否按场景跳转到对应页，而非首页）
  · scene 参数是否正确解析（如扫码带 id=123 是否直达详情页）
  · 未登录时的处理（分享给新用户，是否需要先授权）
```

> ⚠️ **高频 Bug**：分享卡片带 `?id=123`，但打开后总是跳首页 —— 因为参数写在 `onLoad` 处理的 page 路径上，而分享的 path 没带参数。

### 3.3 授权与登录

**登录流程（必须理解，接口测试用得上）：**

```text
① 小程序 wx.login()         → 拿到临时凭证 code（5 分钟有效，只能用一次）
② code 发给开发者服务器
③ 服务器用 code + appid + secret 调微信 jscode2session 接口
      → 返回 openid + session_key（+ unionid，若绑定开放平台）
④ 服务器生成自定义登录态（token）返回小程序
⑤ 小程序存 storage，后续请求带 token
```

**授权类型：**

| 授权 | API / 组件 | 测试点 |
| :--- | :--- | :--- |
| 用户信息 | `<button open-type="getUserInfo">` / `wx.getUserProfile` | 头像昵称获取（现多用头像昵称填写能力） |
| 手机号 | `<button open-type="getPhoneNumber">` | **需企业主体**，解密失败的处理 |
| 位置 | `wx.getLocation` / `wx.chooseLocation` | 拒绝授权、系统定位未开 |
| 相册/相机 | `wx.chooseImage` / `wx.chooseMedia` | 拒绝授权后再次唤起 |
| 麦克风/录音 | `wx.getRecorderManager` | 权限拒绝提示 |
| 蓝牙/通讯录/日历 | 各自 API | 同上 |
| 订阅消息 | `wx.requestSubscribeMessage` | 勾选"总是保持以上选择"的行为 |

**授权测试标准动作（每个授权都要走一遍）：**

```text
1. 首次使用 → 弹窗 → 允许 → 功能正常
2. 首次使用 → 弹窗 → 拒绝 → 是否有友好提示 + 能否重新唤起
3. 拒绝后再次点击 → 是否能再次弹窗（或引导去设置页）
4. 系统层面关闭权限（手机设置里关）→ 小程序内是否有提示并引导
5. 已授权 → 卸载微信重装 / 换设备登录 → 授权状态是否同步
6. 授权弹窗期间切后台再回来 → 不会卡死
```

> 💡 **"拒绝后不能再弹出"**是经典问题：微信的授权弹窗用户拒绝后，短时间内再调不会再弹，需要开发做引导到设置页（`wx.openSetting`）的处理。

### 3.4 支付测试（微信支付，重点）

**流程**：下单（服务端统一下单）→ 拿到 `timeStamp/nonceStr/package/signType/paySign` → `wx.requestPayment` → 输入密码 → 支付结果回调 → 服务端查单确认 → 更新订单状态

**测试矩阵：**

| 场景 | 预期 |
| :--- | :--- |
| 正常支付成功 | 订单变已支付，支付记录生成 |
| **支付中取消** | 订单仍为待支付，可重新发起（不能生成重复订单） |
| 余额不足/密码错误 | 明确提示，订单状态不变 |
| 支付成功但网络中断 | 以**服务端查单结果**为准（不能只信客户端回调） |
| 快速点两次支付 | 只能付一次（幂等） |
| 支付后返回按钮 | `navigateBack` 回到的页面状态正确 |
| 退款 | 全额/部分退款，金额与状态正确 |
| 金额篡改 | 抓包改金额 → **服务端必须重新计算**（见安全测试篇） |
| 小额验证 | 0.01 元、超大金额、负数 |

> ⚠️ **重点**：微信支付回调是**异步**的，客户端 `success` 只代表微信侧成功，**订单状态必须以服务端查单为准**。测试方法：支付后立即断网，看订单最终是否变为已支付。

### 3.5 分享与转发

| 能力 | API | 测试点 |
| :--- | :--- | :--- |
| 转发给好友/群 | `onShareAppMessage` | 标题、图片、path 参数、自定义按钮转发 |
| 分享到朋友圈 | `onShareTimeline` | **单页模式**（无登录态、部分能力不可用★） |
| 生成小程序码/二维码 | 服务端 `wxacode.get` / `getUnlimited` | scene 参数解析（getUnlimited 的 scene 最长 32 字符） |
| 分享后数据统计 | 后台"分享"埋点 | 分享次数、回流率 |

> ⚠️ **朋友圈单页模式**是高频坑：从朋友圈打开时是"单页模式"，**不支持登录态、不支持跳转其他页面、部分组件不可用**。必须单独测这条路径，否则用户从朋友圈进来看到的是空白或报错。

### 3.8 数据缓存（Storage）

```javascript
wx.setStorageSync('key', value)      // 同步
wx.setStorage({ key, data })         // 异步
wx.getStorageSync('key')
wx.removeStorageSync('key')
wx.clearStorage()
```

**限制与测试点：**

| 项 | 说明 |
| :--- | :--- |
| 容量 | 单个小程序约 **10MB**（以官方为准） |
| 隔离 | 按 **用户 + 小程序** 维度隔离（换账号数据不共享） |
| 清理 | 微信可能主动清理（长时间未使用、空间不足） |
| **测试点** | 缓存失效后是否有兜底；退出登录后缓存是否清除；换账号是否串数据 |

> 💡 **高频 Bug**：退出登录后只清了 token，没清业务缓存 → **下一个账号看到上一个账号的数据**（信息安全问题）。

### 3.9 分包与更新

```text
主包 ≤ 2MB，整包 ≤ 20MB（以官方文档为准，不同时期有调整）
分包：subPackages 配置，可按需加载

测试点：
□ 首次进分包页是否有加载提示（不能白屏）
□ 分包预下载规则（preloadRule）是否生效
□ 分包大小超限时的表现
□ 版本更新：wx.getUpdateManager()
    · 新版本发布后，老用户冷启动是否收到更新提示
    · 强制更新 / 静默更新 的行为是否符合预期
    · 更新后本地缓存数据是否兼容（旧数据结构）
```

## 四、性能测试

### 4.1 体验评分（Audits）

开发者工具 → **体验评分 / Audits** → 自动跑分，给出问题与优化建议。

**官方建议值（参考）：**

| 指标 | 建议 |
| :--- | :--- |
| 首屏渲染时间 | ≤ 5s |
| 渲染时间 | ≤ 500ms |
| 脚本执行时间 | ≤ 1s |
| `setData` 单次数据 | < 256KB（建议 < 64KB） |
| 页面节点数 | < 1000（建议 < 500） |
| 图片大小 | > 100KB 建议压缩 |
| 网络请求耗时 | < 1s |
| WXML 节点层级 | < 30 层 |

### 4.2 setData 优化（小程序性能第一杀手）

```javascript
// ❌ 错误：频繁调用
this.setData({ count: 1 });
this.setData({ name: 'a' });

// ✅ 正确：合并
this.setData({ count: 1, name: 'a' });

// ❌ 错误：传整个大对象
this.setData({ list: this.data.list });

// ✅ 正确：只传变化的部分（路径写法）
this.setData({ 'list[0].name': 'new' });

// ❌ 错误：后台页面还在 setData
// ✅ 正确：onHide 时停止数据刷新与定时器
```

**测试方法：**
1.  开发者工具的 **Trace / Performance 面板**，看 `setData` 耗时与频率
2.  真机上用 **PerfDog** 或微信自带的性能面板
3.  长列表快速滑动，观察是否卡顿（FPS < 50 即为不流畅）

### 4.3 启动性能

| 类型 | 定义 |
| :--- | :--- |
| **冷启动** | 首次打开 / 被销毁后重新打开（含代码包下载） |
| **热启动** | 切后台 5 分钟内再打开 |

**测试点：**
- [ ] 冷启动耗时（目标 ≤ 3s，含首屏内容可见）
- [ ] 首屏是否有骨架屏/loading，而非白屏
- [ ] 热启动是否恢复到之前的页面（而非回首页）
- [ ] 启动时的网络请求数是否合理（不要串行依赖太多）

### 4.4 弱网与网络测试

| 场景 | 预期 |
| :--- | :--- |
| 断网 | 友好提示 + 重试入口（不能白屏/卡死） |
| 弱网（2G/高延迟） | loading 状态、超时处理 |
| 网络切换（WiFi ↔ 4G） | 请求不中断、能重试 |
| **重复提交** | 弱网点两次提交按钮 → 不能产生双订单 ★ |
| 接口超时 | 有超时时间（默认 60s，建议设更短） |

> 💡 弱网模拟用 Charles 的 Throttle，详见 [抓包工具]({%post_url 2026-10-21-抓包工具%}) 篇。真机弱网也可用 QNET、弱网王等工具。

### 4.5 内存与稳定性

- [ ] 长时间使用内存是否持续增长（泄漏）
- [ ] 快速反复进出某页面，是否累积内存
- [ ] 长列表无限滚动（几万条）是否崩溃
- [ ] 图片列表加载大量大图是否 OOM
- [ ] 后台切换 50 次是否稳定

> 稳定性压测思路可参考 [Monkey稳定性测试]({%post_url /Details/2026-04-13-Monkey稳定性测试%})（小程序需借助微信内的随机操作或自研脚本）。

## 六、自动化测试方案

### 6.1 方案对比

| 方案 | 原理 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **Minium**（官方）★ | Python，控制开发者工具或真机 | **官方支持、能跨自定义组件、支持真机** | 需装开发者工具，环境略重 |

### 6.3 Minium 第一个用例

```python
# test_login.py
import minium


class TestLogin(minium.MiniTest):
    """继承 MiniTest，即可用 unittest 的全部断言"""

    def test_login_success(self):
        # 1. 跳转页面
        self.app.navigate_to("/pages/login/index")

        # 2. 定位元素并操作
        self.page.get_element("#username").input("testuser")
        self.page.get_element("#password").input("123456")

        # 3. 点击
        self.page.get_element(".login-btn").click()

        # 4. 等待并断言
        self.page.wait_for(".user-info", max_timeout=10)
        nickname = self.page.get_element(".nickname").inner_text
        self.assertIn("testuser", nickname)

    def test_login_empty_password(self):
        self.app.navigate_to("/pages/login/index")
        self.page.get_element("#username").input("testuser")
        self.page.get_element(".login-btn").click()
        # 断言错误提示出现
        self.assertTrue(self.page.wait_for(".error-tip", max_timeout=3))
```


### 6.5 PO 模式封装

```python
# pages/login_page.py
import minium


class LoginPage:
    """登录页对象"""

    def __init__(self, mini: minium.MiniTest):
        self.mini = mini

    def open(self):
        self.mini.app.navigate_to("/pages/login/index")
        self.mini.page.wait_for("#username")
        return self

    def login(self, username: str, password: str):
        self.mini.page.get_element("#username").input(username)
        self.mini.page.get_element("#password").input(password)
        self.mini.page.get_element(".login-btn").click()

    def get_error_tip(self) -> str:
        el = self.mini.page.get_element(".error-tip")
        return el.inner_text

    def is_login_success(self) -> bool:
        return self.mini.page.wait_for(".user-info", max_timeout=10)
```

## 七、抓包与接口测试

### 7.1 小程序的网络请求

```javascript
wx.request({
  url: 'https://api.example.com/order/list',
  method: 'POST',
  data: { page: 1 },
  header: { 'content-type': 'application/json', 'token': 'xxx' },
  success: (res) => { },
  fail: (err) => { }
})
```

**约束：**
*   必须 **HTTPS**
*   域名必须在后台配置 **request 合法域名**
*   不能有端口、不能用 IP
*   并发上限 10 个（wx.request / uploadFile / downloadFile 各自限制）

### 7.2 抓包方法

| 环境 | 方法 |
| :--- | :--- |
| **开发者工具** | 调试器 → Network 直接看（最简单） |
| **iOS 真机** | Charles 装证书 + 描述文件信任 |
| **Android 真机** | Android 7+ 用户证书不信任 → 需 root 装系统证书，或用低版本 Android |
| 通用 | 开发者工具"真机调试"看 Network |

```text
Charles 抓小程序步骤：
1. 手机 WiFi 代理指向电脑（同抓包工具篇）
2. 手机安装并信任 Charles 证书
   iOS：设置 → 通用 → 关于本机 → 证书信任设置 → 打开开关 ★
   Android 7+：用户证书对 App 不生效，需 root 或用 Android 6 及以下设备
3. Charles 开启 SSL Proxying，添加小程序域名
4. 手机上打开小程序，即可看到请求
```

> 详细步骤见 [抓包工具]({%post_url 2026-10-21-抓包工具%}) 篇。小程序强制 HTTPS，所以证书这一步绕不开。

### 7.3 接口测试要点

- [ ] **合法域名**：正式环境是否能正常请求（开发时勾了"不校验"，上线忘配会全挂）★
- [ ] **鉴权**：不带 token / 过期 token / 他人 token（越权）
- [ ] **参数校验**：服务端二次校验（金额、数量、状态）
- [ ] **返回数据脱敏**：手机号、身份证
- [ ] **并发限制**：小程序并发 10 个上限的表现
- [ ] **超时处理**：接口慢时前端是否有 loading 与超时提示

> 安全测试要点见 [安全测试]({%post_url 2026-10-27-安全测试%}) 篇（越权、金额篡改、敏感信息）。

## 八、合规与审核（小程序特有）

提交审核前必须自查，被拒会拖慢上线：

| 常见被拒原因 | 自查项 |
| :--- | :--- |
| **功能不完整** | 提供了测试账号密码？体验版能正常跑通全流程？ |
| **诱导分享/关注** | 是否有"分享后才能使用""关注公众号才能领奖" |
| **虚拟支付** | iOS 端小程序**不允许**虚拟商品用微信支付（如充值会员、虚拟币） |
| **类目不符** | 小程序实际功能与所选类目一致？涉及特殊行业需资质（医疗/金融/教育） |
| **内容违规** | 敏感词、色情、政治、侵权内容 |
| **用户信息收集** | 是否有隐私协议？是否在收集前告知？ |
| **未提供客服** | 是否配置了客服功能 |
| **名称/简介** | 含违规词、与实际不符、侵犯他人商标 |

> 💡 **测试同学要做的**：在"提审前"用**体验版**完整走一遍新用户全流程（注册 → 授权 → 主流程 → 支付），确保审核人员按默认路径能跑通。

## 九、常见问题速查

| 问题 | 原因 | 解决 |
| :--- | :--- | :--- |
| 扫体验版二维码提示"无权限" | 不是体验成员 | 让管理员在后台"成员管理"添加 |
| 真机白屏 | 域名未配合法域名 / 代码报错 | 看 vConsole 日志；检查后台域名配置 |
| 开发者工具能跑，真机不行 | 证书/域名/基础库差异 | 真机调试看日志 |
| 分享打开跳首页 | path 未带参数或参数解析错 | 检查 `onShareAppMessage` 的 path |
| 从子页返回数据不刷新 | 逻辑写在 `onLoad` | 应写在 `onShow` |
| 连续跳转后点不动 | 页面栈满 10 层 | 用 `redirectTo` 或 `reLaunch` |
| 授权弹窗不再出现 | 微信限制，拒绝后短时间内不弹 | 引导 `wx.openSetting` |
| 支付后订单未更新 | 只信了客户端回调 | 服务端主动查单 |
| iOS 无法支付 | 虚拟商品 iOS 不支持微信支付 | 改为实体商品或用其他方式 |
| 抓不到 HTTPS 包 | Android 7+ 证书限制 | root 装系统证书 / 换低版本设备 |
| 元素定位不到自定义组件内的元素 | 未穿透 | 用 `>>>` 选择器 |
| 原生组件无法点击 | video/map 层级最高 | 真机模式或坐标点击 |
| 更新后老用户看到旧版 | 未处理更新逻辑 | 用 `wx.getUpdateManager()` |
